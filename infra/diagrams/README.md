# Диаграммы инфраструктуры

В этом каталоге лежат готовые диаграммы для защиты и документации по отказоустойчивому кластеру Docker Swarm.

## Состав

### `01-cluster-topology.mmd`
Описание:
- общая топология стенда;
- показывает все роли: `LB`, `manager`, `worker`;
- показывает VIP, кворум manager-нод и направление HTTP/control-plane трафика.

Когда использовать:
- для слайда с архитектурой всего решения;
- для ответа на вопрос "из каких узлов состоит кластер".

### `02-request-flow.puml`
Описание:
- путь пользовательского запроса от клиента до реплики сервиса;
- показывает цепочку `VIP -> HAProxy -> worker -> Swarm -> replica`;
- включает сценарий отказа активного балансировщика.

Когда использовать:
- для объяснения, как именно запрос попадает в сервис;
- для ответа на вопрос "почему при отказе LB адрес не меняется".

### `03-service-distribution.mmd`
Описание:
- распределение ролей и сервисов по нодам;
- разделяет edge layer, control plane и workload plane;
- показывает, что HTTP идет только на worker-ноды, а manager-ноды держат quorum.

Когда использовать:
- для объяснения, где крутятся прикладные сервисы;
- для ответа на вопрос "почему managers не должны нести обычный HTTP-трафик".

### `04-failover-scenarios.puml`
Описание:
- логика отказоустойчивости;
- показывает реакцию на отказ активного LB, worker и manager;
- показывает условие кворума `2 из 3 manager`.

Когда использовать:
- для слайда про отказоустойчивость;
- для описания failover-сценария на защите.

### `05-network-model.mmd`
Описание:
- отдельная схема сети;
- показывает, какой интерфейс "смотрит внутрь", а какой "наружу";
- объясняет роль `Host-Only` и `NAT`.

Когда использовать:
- для ответа на вопрос "как устроена сеть в кластере";
- для объяснения, как формируются IP и через какой интерфейс идет SSH, VIP и egress.

## Форматы

- Mermaid:
  - GitHub умеет рендерить Mermaid в Markdown-блоках;
  - draw.io умеет импортировать Mermaid через `Arrange -> Insert -> Advanced -> Mermaid`.
- PlantUML:
  - подходит для sequence/activity диаграмм;
  - удобно использовать в отчетах и презентациях.

## Архитектурные допущения

- профиль стенда: `3 manager + 2 worker + 2 load balancer`;
- VIP: `192.168.56.10`;
- LB-ноды:
  - `kp-lb-01 = 192.168.56.31`
  - `kp-lb-02 = 192.168.56.32`
- manager-ноды:
  - `kp-manager-01 = 192.168.56.11`
  - `kp-manager-02 = 192.168.56.12`
  - `kp-manager-03 = 192.168.56.13`
- worker-ноды:
  - `kp-worker-01 = 192.168.56.21`
  - `kp-worker-02 = 192.168.56.22`
- HTTP-трафик HAProxy отправляет только на worker-ноды;
- трафик control-plane Swarm идет на manager-ноды по `:2377`;
- каждый узел использует:
  - `enp0s3` для внутренней сети `Host-Only`;
  - `enp0s8` для внешнего выхода через `NAT`.
